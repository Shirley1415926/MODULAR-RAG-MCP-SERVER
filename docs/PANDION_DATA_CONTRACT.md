# Pandion Dashboard：统一模拟数据与指标口径（2026-09-17）

## 给非技术读者的说明

原来有些数字是写在网页里的，再随筛选乘一个系数；现在先生成一笔笔预约，三个页面从同一批记录计算。SQLite 是电脑里的账本，公开网页使用这本账导出的纯虚拟数据，不直接连接电脑，也不包含 API key。

公司是真实的，需求来自实习项目；患者、服务人员姓名、排班、反馈、收入和运营事件全部是虚构的。这不是公司真实经营结果，也不是经过匿名化的真实患者数据。

## 公开依据与假设的边界

查阅日期：2026-09-17。

- [团队页面](https://www.pandionhealth.com.au/team/)：按不同成员计数为 12 位精神科医生、6 位儿科医生、10 位心理/治疗服务人员、3 位 ADHD 教练、2 位 allied health 服务人员，共 33 位。它不是在职 FTE 或实际每周出诊人数的证明。模拟姓名与真人姓名不同。
- [收费页面](https://www.pandionhealth.com.au/pricing/)：标示累计 3,000+ 次评估，不能据此推断当前活跃患者数。因此 **1,800 位患者是演示假设**，不是查到的公司数据。保留 AUD、远程服务与部分挂牌收费，未建模所有服务套餐。
- [财务与取消政策](https://www.pandionhealth.com.au/financial-consent-and-cancellation-policy/)：迟取消可能产生费用，所以诊疗收入与取消费用分别记账。

模拟采用成人精神科、6–16 岁儿科及成人其他服务的子集；并非复制公司的全部年龄覆盖。心理/治疗类别保留分组，但不把教练和治疗师一律称为 Dr。

## Admin 页面

统一筛选：角色、状态组、最近 7/30/90 天。日期范围两端都包含；同比为紧邻的等长上一周期，不重叠。

| 页面元素 | 实际计算口径 |
| --- | --- |
| Service revenue (AUD) | 完成诊疗的预约价格之和；取消、改期、未出席、未来预约为 0 |
| Cancellation fees | 单独列在对账说明/证据里，按取消通知时长模拟；不混入诊疗收入 |
| Appointment attempts | 每个原始时间安排是一条尝试，改期旧记录也算一条；不等于最终成功就诊次数 |
| All Status | Confirmed + Rescheduled + Cancelled，三个互斥组 |
| Confirmed | 未取消/未改期组；历史出席结果另分 completed/no_show，未来为 confirmed |
| Unique patients | 筛选范围内去重患者数；不同状态或日期的患者数不可直接相加 |
| Occupied capacity | 完成/未出席的占用分钟数 ÷ 同角色同期提供的排班分钟数；取消/改期占用为 0 |
| KPI 小折线、变化率 | 与大图相同记录、相同日期分桶；上一期为 0 时显示 New activity，不显示无穷大 |
| Appointment Statistics | 同筛选的状态计数；按日期分桶展示堆叠柱图 |
| Daily Appointment | 真正的演示月日历，仅允许选当前范围；列表与 View all 使用同一天的真实模拟记录 |
| Profession 图与热力图 | 分角色加权分钟利用率；热力图把所选历史窗口分成至多 5 桶，不再混用未来月份 |
| Patient Trend | 恢复原型四类正负堆叠柱状图；按日期、医生角色筛选生命周期事件，不随预约状态筛选；向下的柱表示状态转移，不是负人数 |
| Reviews | 当前预约关联的问卷均分与样本数；完成诊疗才有服务质量评分；总体评分 <3 的记录数 |

“Cancelled share of selection”是在当前筛选里的占比。只看 Cancelled 时自然是 100%，不能把它解释成整个诊所的取消率。
费用以整数分存储。这里是简化服务收入模型，不是财务总账：没有实现收款分期、税、医保结算、平台手续费、拒付或所有退款流程，不能据此做财务申报。

## Clinician 页面

统一筛选：角色、初次评估/后续预约、未来 2/4/8 周，从基准日次日开始。

- Offered hours = 排班分钟数；Booked hours = 未来已确认预约占用；Unbooked = Offered − Booked。85% 是演示目标，不是公司真实 KPI。
- Hours to target = max(0, offered×85%−booked)。实际按分钟算，小时展示可能有四舍五入。
- 待分配队列只有尚未存在未来确认预约的患者。匹配要求角色、预约类型、时间偏好一致；连续照护患者还要求原医生一致。匹配数是候选人数，不表示已经分配，也不能跨医生重复相加。
- 风险 badge 为高优先级、等候超过 7 天、需要复诊但没有下一预约的患者 **去重并集**。三个类别可能重叠；7 天 SLA 是模拟规则。
- 复诊风险来自最近已完成预约的 followup_due，需在所选未来窗口截止前到期，包含已经逾期的情况。
- 预计填满时间 = 达标缺口 ÷ 过去四周每周已确认占用时长。这只是按历史服务量估算的情景指标，不是预测模型；不代表等候患者就能填完所有空档。
- 热力图统计下一周/最多未来四周的工作日小时段占用比例；没有提供排班显示 —，不是 0% 需求。所有时间统一以 Australia/Sydney 表示。
- 名单搜索、利用率排序、导出、查看候选可使用。新建医生、排班、预约是只读原型未实现的写入流程，明确禁用。

## Patient Feedback 页面

- 日期、医生、患者分组和预约类型筛选全部基础记录。高风险是独立属性，可以与新/持续患者重叠。
- Telehealth 是所有预约的服务方式，不再与 Assessment/Follow Up 混为互斥类型。后续预约可包括第二次评估和持续复诊，费用依据 service_code 区分。
- 取消率/未出席率分母都是同范围的全部预约尝试（包含改期）。原因筛选只缩小对应指标的分子，不删除分母中的其他预约；两类原因互不干扰。问卷与主题保留基础人群范围，这个例外在页面底部明确说明。
- 7/30 天逐日展示；90 天分桶后重新用次数计算比例，不平均各天百分比。休息日无预约显示断点，不伪造 0% 或未来预测。
- 两张比例图共享从 0 开始的坐标上限，依据同人群 90 天每日最大值决定，切换 7/30/90 天不改变比例尺，防止夸大变化。
- 评分显示有效样本量。没有完成诊疗的反馈可以评价预约体验中的流程，但不会产生诊疗质量/实际就诊体验评分。
- 主题频率来自所有匹配反馈，每条有一个预标注主主题；不是用 Top-K 相似记录猜频率，也不是已完成自动主题识别算法。少于 5 条时不形成主题排名结论。

### 原型样式修复（2026-09-17）

后续用户明确以 `Pandion/Dashboard V14.html`（包含 RAG 按钮）作为最终设计基准。本次直接从该原文件重建 dashboard.html，保留原始首个样式表逐字不变，移除之前修改卡片高度、数字字号、日历高度的覆盖规则。原脚本的硬编码数据替换为现有账本聚合；不回退已验证的收入/状态计算。取消率图恢复橙色直线和圆角方形节点；未出席率恢复浅紫色；医生横条恢复五色、列表恢复头像和彩色进度条、预订热图恢复紫色。额外保留用户要求的评分标题及删除评分绿色小字。主题名称和数值来自现有模拟问卷，不抄回原型的保险等假主题。`tests/pandion_design.test.cjs` 固定 V14 原始样式表 SHA-256，防止后续再次无意改版。下文较早的 320px 卡片/平滑曲线等展示决策如有冲突，以 V14 原样式为准。

- Patient Trend 的事件由完成预约推导：首次完成为 New；超过 45 天后再次完成为 Reactivated；45 天未完成为 Inactivity；90 天为 Inactivated。基线既往患者从观察期前一天计算。这是虚拟运营演示规则，不是公司的政策，也不是临床出院判断。事件保留预约来源；状态过渡事件指向最近完成预约或基线。
- Overview 迷你图恢复折线/柱状/柱状/折线组合，数据是逐日滚动 7 天汇总。预约数和患者数可能接近或相同，这是模拟数据在短期内很少复诊造成的，不人为修改曲线。
- 30 天图按连续日期区间汇总，每个区间都显示标签；7 天反馈率图仅显示有排班或预约的服务日，避免把休息日误画成 0% 或断线。
- Negative Feedback Themes 恢复原型四色、细条、五分制展示。数值是新增模拟问卷字段 `complaint_impact_score`（1=轻微，5=严重）的均值，条长=均值/5，不是主题占比或从频率换算的分数。完整主题次数仍用于分析和证据详情。该字段为虚拟问卷数据，不代表公司已有该问项。
- 评分区标题 Patient Feedback Scores，移除绿色样本/比较注释；样本数可悬停查看，详细口径通过 About these metrics 打开。主页面保留简短虚拟数据标识。
- 9 月 9–12 日的提醒问题是为了演示而构建的事件，不是公司真实事故。仍保留正面反馈，不把一切变化归因于这个事件。

## 证据与 RAG 的边界

2026-09-18 展示修正：按用户要求保留 V14 页面布局、Allocation Risk Panel 固定高度卡片、彩色图标及 Key Operational Insights 原有横向卡片样式。主页面只显示重点标题、简短提示和 View detailed explanation 小按钮；分析范围、状态、详细影响、完整建议及引用统一放在已有覆盖式侧面板中。异步 AI 完成不改变主页面卡片高度。以下分析逻辑仍保留，但所有长解释均不在主页面直接铺开。

公开 GitHub Pages 为静态站：所有计数与证据面板动态读取当前筛选后的同一账本，无 API key，也没有现场调用 DeepSeek。明确标注 computed evidence，不再显示过期的 portfolio snapshot 或虚假的 grounding 百分比。

本地页面的 Allocation Risk Panel 和 Key Operational Insights 在进入页面或改变筛选后自动分析，不再要求点击 Generate/Explain。Overview 的四个 Why 按钮已移除。每个重点直接显示发现、影响和下一步，View evidence 展开当前支持记录和生成时引用的演示 SOP。

`clinic_model.js` 按当前账本筛选并排序最多三个重点，不强行凑满。Allocation 依次关注无匹配时段的高优先级需求、逾期复诊、有匹配时段的高优先级需求、其他超期等待、即将到期复诊。Feedback 的出席异常要求当前/上期均至少 20 条预约、至少 3 个相关结果，且比例增加至少 3 个百分点；负面主题要求至少 5 条反馈、该主题至少 3 条且占比至少 15%。这些是演示规则，不是统计显著性或公司批准的阈值。原因下拉框只影响对应图表，优先事项始终使用日期/医生/人群/预约类型选定的完整人群，面板明确显示这一边界。

新增 `POST /api/operational-review`：接收前端确定性计算的重点和完整支持记录 ID；后端核验 ID 并从新版账本重新读取代表记录，仅从旧检索库取适用的 SOP/policy，不使用旧患者/运营事件作为新版事实。模型为每个重点补充简短解释和建议，输出必须保留重点 ID 并引用实际检索出的 SOP。数字、排序和阈值仍由规则模型决定，不声称由模型自主发现所有异常。当前接口信任前端提供的聚合描述，并未独立重算全部筛选/阈值，不应视为生产级服务端统计校验。

本地请求延迟 700ms 合并，切换筛选取消旧请求并拒绝过期结果，成功生成按当前会话的完整输入缓存，60 秒超时后保留规则建议。缺少 SOP、模型失败或引用/结构校验失败时明确保留规则分析；公开静态页面不调用 API。未实现公共后端部署或生产访问控制。

旧 sample_data/golden set 留作先前检索算法的回归夹具，不用于新版页面的经营指标或反馈频率。旧跨场景检索基准分数不能当成本次 2,707 条反馈的新增评测成绩。原 `/api/insights` 保留兼容，当前页面使用新的 operational-review；新版 Admin 不提供 AI 原因分析。
